1. Claude Code nədir?

Claude Code proqram yazmaq üçün agentdir. Siz ona tapşırıq verirsiniz, o isə layihənizin fayllarını oxuyur, kodu dəyişir, əmrləri işə salır və nəticəni yoxlayır.

Adi çat ilə fərq böyükdür. Çatda siz kodu kopyalayıb göndərirsiniz, cavabı da özünüz geri köçürürsünüz. Claude Code isə birbaşa sizin layihənizin içində işləyir:

Adi çatClaude Code
Kodu siz kopyalayıb yapışdırırsınızLazım olan faylları özü tapıb oxuyur
Təklif verir, tətbiq etmək sizdədirFaylları özü redaktə edir (icazənizlə)
Kodun işlədiyini bilmirTestləri, build-i işə salıb nəticəyə baxır
Hər dəfə konteksti izah etməlisinizLayihənin qaydalarını CLAUDE.md faylından xatırlayır

Harada işləyir?

  • Terminal (CLI): əsas forma. Layihə qovluğunda claude yazırsınız.
  • IDE: VS Code və JetBrains üçün genişlənmələr var. Dəyişiklikləri redaktorun özündə görürsünüz.
  • Masaüstü tətbiq və veb (claude.ai/code): bulud sessiyaları. Kompüteriniz söndürülü olsa belə, iş buludda davam edir.
  • GitHub: issue və ya PR-da @claude yazmaqla tapşırıq vermək olar.
📌 Real nümunə: bu Akademiya

İndi oxuduğunuz bu tətbiq Claude Code ilə, bulud sessiyasında quruldu. Siz Azərbaycan dilində yazdınız: “mənə məntiq kursu hazırla”, “LMS platforması yarat”, “telefona quraşdırılsın”. Claude Code isə faylları yaratdı, brauzerdə test etdi, ikonları çəkdi, GitHub-a göndərdi və dərcin uğurlu olduğunu yoxladı. Siz bir sətir də kod yazmadınız, amma hər vacib qərarı siz verdiniz: Digital Nation-a toxunmamaq, reponu public etmək və s.

Əsas fikir: Claude Code bacarıqlı bir köməkçi proqramçıdır. Ona yaxşı tapşırıq vermək, işini yoxlamaq və vacib qərarları özündə saxlamaq sizin işinizdir. Bu kurs məhz bunu öyrədir.

2. Quraşdırma və ilk sessiya

Quraşdırma

macOS və Linux üçün rəsmi quraşdırıcı:

curl -fsSL https://claude.ai/install.sh | bash

Windows (PowerShell):

irm https://claude.ai/install.ps1 | iex

Node.js quraşdırılıbsa, npm ilə də olar:

npm install -g @anthropic-ai/claude-code

İlk açılışda hesabınıza daxil olmağınız istənir. Claude abunəliyi (Pro, Max, Team və s.) və ya API açarı ilə daxil olmaq mümkündür.

    3. Yaxşı tapşırıq (prompt) yazmaq

    Claude Code-un nəticəsinin keyfiyyəti çox vaxt tapşırığın keyfiyyətindən asılıdır. Claude sizin beyninizi oxuya bilmir: bildiyiniz, amma yazmadığınız hər şey onun üçün yoxdur.

    Yaxşı tapşırığın 6 elementi

    1. Məqsəd: nə etmək lazımdır? (“düzəlt”, “əlavə et”, “yenidən yaz”)
    2. Yer: hansı fayl, hansı hissə? @src/login.js
    3. Səbəb və kontekst: niyə? Problem nədir, xəta mesajı nədir?
    4. Məhdudiyyətlər: nəyə toxunmamalı, hansı kitabxananı işlətməməli?
    5. Uğur meyarı: iş bitəndə nə görməliyik?
    6. Yoxlama: “testləri işə sal”, “brauzerdə yoxla”.
    📌 Real nümunə: zəif və güclü tapşırıq

    Zəif: “login işləmir, düzəlt”

    Güclü: “@src/auth/login.js faylında istifadəçi düzgün parolla daxil olanda 'Invalid token' xətası çıxır (log aşağıdadır). Problem dünənki commit-dən sonra başlayıb. Səbəbi tap və düzəlt. Verilənlər bazası sxeminə toxunma. Sonra npm test işə sal və login testlərinin keçdiyini göstər.”

    İkinci tapşırıqda Claude-un təxmin etməli olduğu heç nə qalmır: harada axtarmaq, nəyə toxunmamaq, işin bitdiyini necə bilmək.

    📌 Real nümunə: şəkil ilə

    Dizayn problemi varsa, ekran şəklini terminala yapışdırın (və ya faylı sürüyüb atın) və yazın: “Mobil görünüşdə menyu bu şəkildəki kimi üst-üstə düşür. Elə düzəlt ki, 390px enində də düzgün görünsün.” Bu Akademiyada da belə edildi: ekran şəkillərinə baxıb düzəlişlər edildi.

    Qızıl qayda: tapşırığı yeni işə başlamış bacarıqlı bir həmkara verdiyinizi təsəvvür edin. Ona nə izah edərdinizsə, Claude-a da onu yazın.

    🔍 Alət: tapşırığınızı yoxlayın

    Tapşırığınızı yazın (Azərbaycan və ya ingilis dilində), alət hansı elementlərin olduğunu və hansılarının çatışmadığını göstərəcək.

    ✍️ Tapşırıq

    4. İş axını: kəşf → plan → kod → yoxla → commit

    Ən çox yayılmış səhv Claude-dan dərhal kod yazmasını istəməkdir. Mürəkkəb işlərdə ən yaxşı nəticəni bu ardıcıllıq verir:

    1. Kəşf: “Ödəniş modulunu oxu və necə işlədiyini izah et. Hələ heç nə dəyişmə.”
    2. Plan: “İndi PayPal əlavə etmək üçün plan qur. Hansı faylları dəyişəcəksən?” Planı oxuyun, lazım olsa düzəldin.
    3. Kod: “Planı tətbiq et.”
    4. Yoxlama: “Testləri işə sal, uğursuz olanları düzəlt.” Və ya: “Brauzerdə aç və ödəniş formasının işlədiyini yoxla.”
    5. Commit: “Dəyişiklikləri aydın mesajla commit et və PR aç.”

    Plan rejimi

    Shift+Tab ilə plan rejiminə keçəndə Claude yalnız oxuyur və təhlil edir, heç bir faylı dəyişmir. Sonda planı sizə təqdim edir. Siz razılaşandan sonra kod yazılır. Bu rejim böyük dəyişikliklərdən əvvəl çox faydalıdır.

    📌 Real nümunə: test əsaslı iş (TDD)

    “Əvvəlcə calculateDiscount funksiyası üçün testlər yaz: 10%, 0%, mənfi məbləğ və 100%-dən çox endirim halları. Testləri işə sal və uğursuz olduqlarını göstər. Testləri commit et. Sonra funksiyanı elə yaz ki, bütün testlər keçsin. Testləri dəyişmə.”

    Claude-un aydın hədəfi (testlər) olanda o, özü yoxlayıb özü düzəldir, siz isə nəticəyə əmin olursunuz.

    📌 Real nümunə: bu Akademiyada yoxlama

    Hər dəyişiklikdən sonra Claude Code tətbiqi görünməyən (headless) brauzerdə açıb testləri işə saldı: telefon enində səhifənin yana sürüşməsi, testlərin işləməsi, oflayn rejim. Bir dəfə məhz bu yoxlama mobil görünüşdə bir xətanı tapdı: ana səhifə dərsin üstündə qalırdı. Xəta sizə çatmamış düzəldildi. Yoxlama olmadan “hazırdır” demək olmaz.

    🧩 Tapşırıq: addımları düzgün sıraya qoyun

    Addımlara düzgün ardıcıllıqla klikləyin.

    ✍️ Tapşırıq

    5. İcazələr və təhlükəsizlik

    Claude Code kompüterinizdə əmr işə sala və faylları dəyişə bilir. Ona görə də standart olaraq riskli addımlardan əvvəl sizdən icazə soruşur.

    İş rejimləri

    RejimNə edirNə vaxt
    Adi (default)Fayl redaktəsi və əmrlərdən əvvəl soruşurYeni layihə, tanımadığınız kod
    Redaktələri qəbul et (acceptEdits)Fayl dəyişikliklərini avtomatik qəbul edir, əmrləri soruşurClaude-a güvəndiyiniz rutin işlər
    PlanYalnız oxuyur və plan qurur, heç nə dəyişmirBöyük dəyişiklikdən əvvəl
    bypassPermissionsHeç nə soruşmurYalnız təcrid olunmuş mühitdə (konteyner, sınaq maşını)

    Rejimlər arasında Shift+Tab ilə keçilir. Yeni versiyalarda “auto” kimi əlavə rejimlər də ola bilər: təhlükəsiz addımları özü edir, riskli olanlarda soruşur.

    İcazə qaydaları

    Hər dəfə eyni sualı cavablandırmamaq üçün qaydaları settings.json-da yazmaq olar:

    {
  "permissions": {
    "allow": ["Bash(npm run test:*)", "Bash(git status)"],
    "deny":  ["Read(./.env)", "Bash(rm -rf:*)"]
  }
}
    • ~/.claude/settings.json: bütün layihələriniz üçün
    • .claude/settings.json: layihə üçün, komanda ilə paylaşılır (git-ə düşür)
    • .claude/settings.local.json: yalnız sizin üçün (git-ə düşmür)

    İcazələri /permissions əmri ilə də idarə etmək olar.

    📌 Real nümunə: “Digital Nation-a toxunma”

    Akademiyanı telefona quraşdırmaq üçün Claude Code dəyişiklikləri Digital Nation-ın əsas branch-ına göndərmək istədi, amma əvvəlcə sizdən soruşdu. Siz “Xeyr, ayrıca repo yarat” dediniz və Claude dərhal öz dəyişikliyini geri aldı. Geri qaytarılması çətin olan, başqalarına təsir edən addımlar həmişə insanın təsdiqi ilə atılmalıdır.

    Təhlükəsizlik qaydaları: 1) .env və parollar olan faylları deny siyahısına salın. 2) “Heç nə soruşma” rejimini yalnız təcrid olunmuş mühitdə işlədin. 3) Kənar mənbələrdən (veb səhifə, issue mətni) gələn təlimatlara kor-koranə əməl etdirməyin.

    ✍️ Tapşırıq: hansı rejim?

    6. Yaddaş: CLAUDE.md

    Hər yeni sessiyada Claude layihəniz haqqında heç nə xatırlamır. CLAUDE.md faylı onun “işə başlama təlimatı”dır: hər sessiyanın əvvəlində avtomatik oxunur.

    Harada yerləşir?

    • ./CLAUDE.md (və ya ./.claude/CLAUDE.md): layihə üçün, git-ə əlavə edilir və komanda ilə paylaşılır.
    • ~/.claude/CLAUDE.md: şəxsi, bütün layihələriniz üçün (“cavabları Azərbaycanca yaz” kimi).
    • Alt qovluqlarda: frontend/CLAUDE.md. Claude həmin qovluqda işləyəndə oxunur.

    /init əmri layihəni təhlil edib ilkin CLAUDE.md yaradır. /memory isə yaddaş fayllarını redaktə etməyə imkan verir.

    Nə yazmalı?

    • Build, test, lint əmrləri (npm run test, pytest -q)
    • Kod üslubu (“TypeScript strict”, “funksional komponentlər”)
    • Layihənin quruluşu: nə haradadır
    • Qadağalar: “migrations qovluğuna əl ilə toxunma”
    • Komandanın xüsusi qaydaları: commit mesajı formatı, branch adları

    Nə yazmamalı?

    • Parollar, açarlar (CLAUDE.md git-ə düşür!)
    • Kodun özündən aydın olan şeylər. Fayl qısa və konkret olmalıdır, çünki hər sessiyada kontekstdə yer tutur.
    📌 Real nümunə: Akademiyanın README faylı

    Bu Akademiyanın reposunda README.md var: tətbiqin quruluşu, yeni kursun necə əlavə olunduğu, dərcin necə işlədiyi. Siz yeni sessiyada “Claude Code kursu əlavə et” yazanda Claude-un bilməli olduğu hər şey orada idi. Bu fayl təxminən CLAUDE.md rolunu oynayır: keçmiş sessiyanın biliyini növbəti sessiyaya ötürür.

    7. Kontekst idarəsi
    
    
    Claude-un “iş masası”nın, yəni kontekst pəncərəsinin ölçüsü məhduddur. Oxunan hər fayl, hər əmr nəticəsi, hər mesaj orada yer tutur.
    
    
    Kontekst doluşduqca köhnə detallar unudulur, cavablar zəifləyir. Ona görə konteksti idarə etmək lazımdır:
    
    
    
      
    ƏmrNə edirNə vaxt
    
      
    /clearSöhbəti tamamilə təmizləyirTamam yeni tapşırığa keçəndə
    
      
    /compactSöhbəti qısa xülasəyə çevirir, vacib olanı saxlayırUzun iş davam edir, amma kontekst dolub
    
      
    /contextKontekstin nə qədər dolu olduğunu göstərirYoxlamaq üçün
    
      
    claude --continueSonuncu söhbəti davam etdirirErtəsi gün işə qayıdanda
    
      
    claude --resume / /resumeKöhnə söhbətlərdən birini seçirƏvvəlki tapşırığa qayıdanda
    
    
    
    
    📌 Real nümunə: bir sessiya, bir mövzu
      
    Səhər login xətasını düzəltdiniz, sonra eyni sessiyada “indi hesabat səhifəsi üçün qrafik əlavə et” yazırsınız. Kontekstdə yüzlərlə sətir login kodu və xəta logu qalıb, bunlar yeni işə lazım deyil. Daha yaxşısı: /clear edib yeni tapşırığa təmiz başlamaq. Bir sessiya, bir mövzu.
    
    
    
    
    📌 Real nümunə: böyük logu birbaşa yapışdırmayın
      
    5000 sətirlik log faylını mesajın içinə yapışdırmaq konteksti bir anda doldurur. Bunun əvəzinə yazın: “logs/error.log faylında 'Timeout' sözünü axtar və son 20 halı təhlil et.” Claude lazım olan hissəni özü tapacaq.

    8. Slash əmrləri və skill-lər
    
    
    Tez-tez təkrarladığınız tapşırıqları bir dəfə yazıb sonra bir sözlə çağırmaq olar.
    
    
    Daxili əmrlər
    
    
    /help, /init, /clear, /compact, /context, /model (model seçimi), /permissions, /memory, /agents, /mcp, /hooks, /resume, /config. Tam siyahını /help göstərir.
    
    
    Öz skill-iniz
    
    
    Skill Claude-a müəyyən işi necə görəcəyini öyrədən qovluqdur. Əsas faylı SKILL.md-dir:
    
    
    .claude/skills/kurs-elave-et/SKILL.md
    
    
    ---
name: kurs-elave-et
description: Akademiyaya yeni kurs əlavə edəndə istifadə et
---
1. courses/<id>/lessons.html faylını yarat: hər dərs bir <section class="lesson">.
2. Hər dərsdə real nümunələr (.ex blokları) və test olsun.
3. courses/<id>/course.js-də LMS.registerCourse çağır.
4. catalog.json-a kursu əlavə et.
5. Brauzerdə yoxla: telefon enində yana sürüşmə olmasın.
    
    
    Skill-i /kurs-elave-et yazaraq özünüz çağıra bilərsiniz. Claude da tapşırıq onun təsvirinə uyğun gələndə onu özü işə sala bilər. Skill qovluğunda köməkçi skriptlər və şablonlar da saxlamaq olar.
    
    
    Köhnə üsul olan .claude/commands/ad.md faylları da işləyir. Mətndə $ARGUMENTS yazsanız, əmrdən sonra yazdığınız mətn ora qoyulur: /fix-issue 123.
    
    
    📌 Real nümunə: komanda üçün “PR yoxlaması”
      
    Komandanızda hər PR yoxlanılarkən eyni şeylərə baxılır: testlər var, xəta mesajları istifadəçiyə aydındır, gizli açar yoxdur. Bunları bir dəfə .claude/skills/pr-yoxla/SKILL.md-də yazıb git-ə əlavə edirsiniz. İndi komandanın hər üzvü /pr-yoxla yazıb eyni keyfiyyətdə yoxlama alır.
    
    
    
  
    
  
    
    
    🃏 Kartlar: əmrləri əzbərləyin
    
    
    Karta basın, cavaba baxın. Hamısını açanda dərs tamamlanır.

    9. Subagentlər

    Niyə lazımdır?
    
    
      
      
    • Kontekst təmiz qalır: 50 faylı axtarmaq subagentin kontekstini doldurur, əsas söhbətə isə yalnız qısa cavab qayıdır.
      • 
      
    • İxtisaslaşma: hər subagentin öz təlimatı, alətləri və modeli ola bilər.
      • 
      
    • Paralellik: bir neçə müstəqil iş eyni anda gedə bilər.
      • 
    
    
    
    Daxili subagentlər var, məsələn kodda axtarış üçün Explore, planlaşdırma üçün Plan. Özünüz də yarada bilərsiniz: /agents əmri ilə və ya fayl kimi:
    
    
    .claude/agents/test-yazan.md
    
    
    ---
name: test-yazan
description: Yeni funksiyalar üçün unit testlər yazır. Kod dəyişəndən sonra istifadə et.
tools: Read, Grep, Glob, Write, Bash
model: sonnet
---
Sən test mütəxəssisisən. Hər funksiya üçün normal hal, sərhəd halları
və xəta halları üçün test yaz. Mövcud test üslubuna uy. Testləri işə sal.
    
    
    📌 Real nümunə: böyük kod bazasında axtarış
      
    “Bu layihədə istifadəçi məlumatları harada şifrələnir?” Əsas Claude 200 faylı özü oxusa, kontekst dolar. Bunun əvəzinə axtarışı Explore subagentinə verir. O, faylları gəzib qaytarır: “3 yerdə: crypto/aes.ts, db/hooks.ts, api/export.ts.” Əsas kontekstə yalnız bu 3 sətir düşür.
    
    
    
    
    📌 Real nümunə: ikinci göz
      
    Claude kodu yazandan sonra “code-reviewer” subagenti işə salınır. Onun konteksti təmizdir, kodu yazan deyil. Ona görə də əsas Claude-un “gözdən qaçırdığı” səhvləri tapmaq ehtimalı daha yüksəkdir, insan komandalarındakı kod yoxlaması kimi.

    11. MCP: Claude-u xarici alətlərə qoşmaq
    
    
    MCP (Model Context Protocol) Claude-u kənar sistemlərə qoşmaq üçün açıq standartdır: GitHub, verilənlər bazası, Figma, Slack, brauzer və s.
    
    
    MCP serveri əlavə etmək:
    
    
    # kompüterdə işləyən server
claude mcp add playwright -- npx @playwright/mcp@latest

# internetdəki (HTTP) server
claude mcp add --transport http github https://api.githubcopilot.com/mcp/

# siyahı
claude mcp list
    
    
    Əhatə dairəsi (scope)
    
    
      
      
    • local (standart): yalnız sizin üçün, bu layihədə.
      • 
      
    • project: .mcp.json faylına yazılır və komanda ilə paylaşılır.
      • 
      
    • user: sizin bütün layihələrinizdə.
      • 
    
    
    
    Sessiya daxilində /mcp serverlərin vəziyyətini göstərir və giriş (login) tələb edən serverlərə qoşulmağa kömək edir.
    
    
    📌 Real nümunə: bu kursun dərci
      
    Bu Akademiya dərc olunanda Claude Code GitHub-a MCP vasitəsilə qoşulmuşdu: dərcin (GitHub Actions) nəticəsinə baxdı, xəta logunu oxudu (“Pages aktiv deyil”) və səbəbi sizə izah etdi. Siz Pages-i aktiv edəndə dərci yenidən özü işə saldı. Brauzerdə GitHub-ı açmağa ehtiyac qalmadı.
    
    
    
    
    📌 Real nümunə: verilənlər bazası
      
    Postgres MCP serveri qoşulubsa, yaza bilərsiniz: “Son 30 gündə qeydiyyatdan keçib heç bir sifariş verməyən istifadəçilərin sayını tap.” Claude sorğunu özü yazıb işə salır. Təhlükəsizlik: belə serverlərə yalnız oxumaq hüququ olan istifadəçi ilə qoşulun.
    
    
    
  
    
  
    ✍️ Tapşırıq
    

    



    
  
    
    
    12. Avtomatlaşdırma: skriptlər, CI və bulud sessiyaları
    
    
    Headless rejim: claude -p
    
    
    -p (print) bayrağı ilə Claude Code interaktiv söhbətsiz işləyir: tapşırığı alır, işi görür, nəticəni çap edir. Bu, onu skriptlərə qoşmağa imkan verir:
    
    
    # tək sual
claude -p "bu layihədə istifadə olunmayan asılılıqları sadala"

# başqa əmrin çıxışını ötürmək
cat error.log | claude -p "bu xətaların ən çox rast gəlinən 3 səbəbini izah et"

# maşın üçün JSON çıxışı
claude -p "testləri işə sal və nəticəni xülasə et" --output-format json
    
    
    GitHub ilə
    
    
    Claude-un GitHub tətbiqini quraşdırsanız (terminalda /install-github-app), issue və ya PR şərhində @claude yazıb tapşırıq verə bilərsiniz: “@claude bu bug-ı düzəlt”. O, branch yaradıb dəyişiklik edir və PR açır.
    
    
    Bulud sessiyaları
    
    
    claude.ai/code və ya Claude tətbiqində sessiya Anthropic-in buludundakı təcrid olunmuş konteynerdə işləyir: repo ora klonlanır, iş orada görülür, nəticə branch-a göndərilir. Kompüteriniz söndürülü olsa belə, iş davam edir. Telefondan da izləmək olar.
    
    
    📌 Real nümunə: siz bunu artıq etmisiniz
      
    Bu Akademiya məhz bulud sessiyasında quruldu. Siz yazırdınız, Claude Code isə konteynerdə faylları yaradır, headless brauzerdə test edir və GitHub-a göndərirdi. GitHub Actions isə hər göndərişdən sonra saytı avtomatik yeniləyirdi. Bu, “söhbət → kod → test → dərc” zəncirinin tam avtomatlaşdırılmasıdır.
    
    
    
    
    📌 Real nümunə: gecə hesabatı
      
    Hər gecə CI-də belə bir addım işə düşür: claude -p "dünən birləşdirilmiş PR-ları oxu və komanda üçün 5 bəndlik dəyişiklik xülasəsi yaz" > xulase.md. Səhər komanda hazır xülasəni görür.
    
    
    
  
    
  
    ✍️ Tapşırıq
